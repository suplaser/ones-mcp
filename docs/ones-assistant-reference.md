## 结论

有参考价值，主要用于确定本项目下一版应支持的业务流程和客户端集成方式。

该项目是网页 AI 助手：通过 MCP 客户端连接 `https://sz.ones.cn/mcp`，动态获取并调用工具。它使用 ONES MCP Token，没有自行实现个人 API Key 对应的 Open API 业务客户端。因此不能直接提供本项目所缺少的 Open API 实现。

## 不能直接照搬的部分

1. **连接方式不同。** 参考项目只连接 HTTP MCP；当前项目提供本地 stdio MCP。若要让该网页助手使用本项目，需要修改客户端接入或单独实现 HTTP 传输。
2. **工具协议不同。** 参考项目对 `create_new_issue`、`get_issue_fields` 等名称有专用处理，还依赖 `data.list` 和旧字段结构；当前项目使用 `ones_*` 名称及自身返回结构。仅替换服务地址无法兼容。
3. **审核界面属于客户端。** 通用 MCP 服务不应依赖其 React 页面和审核接口；读写属性只是客户端提示，不能当作服务端授权机制。
4. **字段兼容仍有缺口。** `agent.mjs:115` 仅从 `data.list` 缓存字段，但 `test/review-agent.test.mjs` 的模拟响应使用 `data.fields`；界面在字段信息缺失时会回退到 `field002`、`field060` 等固定 ID。动态字段链路需要补充覆盖，不能视为已完整验证。
5. **防重复创建主要依靠提示词。** 系统提示词要求结果未知时先查重，但不能将其当作服务端幂等保障。后续写入超时应报告结果未知，避免自动重试创建。
6. **已有测试不等于远端验证。** 真实工具测试、Agent 审核测试和 UI 测试分别由环境变量开启；部分测试使用模拟 MCP。本次未运行这些测试，也未验证参考项目的实际远端权限。

## 下一版建议

先完善查询，再接入写操作：

1. 补充当前用户、团队等上下文查询，减少用户手动提供 ID 的步骤。
2. 补充项目内工作项类型、字段及必填规则查询，为后续创建和修改提供依据。
3. 根据官方 Open API 实际支持情况扩展工作项检索，并让分页结果适合 AI 阅读。
4. 在上述基础上增加创建、修改工作项，再单独增加实际工时登记；执行参数与用户批准的内容保持一致。

0.2.0 已补充当前用户、团队、用户搜索、团队工作项类型、完整属性目录及项目详情表单字段查询，并通过真实只读验证。详情表单字段不等于完整的新建必填规则。增强工作项检索、创建、修改和工时登记仍是后续候选范围。

0.3.0 继续补充属性选项、团队状态、可执行工作流、评论、简单模式已登记工时列表及详情查询，工具总数为 17。真实部署的选项偏移与评论响应差异见 [接口覆盖说明](openapi-coverage.md)。这批仅完善读取能力，尚未增加创建、修改、状态流转执行或工时登记。

0.4.0 已增加创建、修改、状态流转与实际工时登记，共计 21 个工具。写入前由服务端使用 MCP 用户确认表单展示完整目标和参数；不支持确认的客户端拒绝写入。模拟测试覆盖批准执行与取消、重放、不确定结果等路径，真实环境仅验证只读预览，未执行业务写入。

0.5.0 增加基于列表游标扫描的组合检索、评论发送/回复/修改/删除、实际工时修改/删除及预估/剩余工时设置，共计 29 个工具（18 读、11 写）。所有写入继续强制用户确认。组合检索提供扫描范围和续查位置，尚未开放 ONESQL；当前部署缺少列表更新时间，相关筛选以缺失字段计数明确反映限制。真实验证仅包含查询及五项只读预览，评论修改/删除因样本中无目标记录由模拟测试覆盖。

0.6.0 增加只读每日工时汇总，共计 30 个工具（19 读、11 写）。使用现有列表接口计算剩余计划的工作日平均分摊及登记工时，按负责人/登记人分别处理人员范围；保留未分摊和不完整原因。该能力由本项目计算实现，不依赖参考助手的固定字段 ID、展示回退或其他 MCP 工具，详细计算口径见接口覆盖说明。

新增能力需要逐项核对官方 Open API、API Key Scope；参考项目中的官方 MCP 工具名称不能作为 Open API 已支持的证据。

原有四个只读业务工具和 API Key 配置流程继续保留。前端、多模型、会话和记忆管理由使用本 MCP 的客户端承担。
