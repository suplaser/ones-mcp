# ONES MCP

让支持 MCP 的 AI 客户端连接 ONES，通过对话查询和处理项目工作项。

本项目使用用户级个人 API Key，包名为 `@suplaser/onces-mcp`。支持查询，以及每次经用户确认后执行的写操作；可访问的数据和操作由你的 ONES 权限决定。

## 可以做什么

- 验证当前用户身份与 API Key 权限范围，查看可访问的团队。
- 搜索团队用户，获取负责人等人员的真实 ID。
- 查看项目列表和项目详情。
- 查询工作项列表，支持按项目和工作项类型筛选。
- 组合筛选标题关键词、负责人或“我负责”、包含/排除状态、创建和更新时间，并返回本次扫描范围及续查位置。
- 查看工作项详情。
- 查询工作项类型、属性目录和项目详情表单字段。
- 查询属性选项，支持关键词、选项 ID 和返回字段筛选。
- 查询团队工作项状态，以及指定工作项当前可执行的工作流。
- 查看工作项评论。
- 查询简单工时模式下的已登记工时列表和记录详情，保留原始小时数。
- 按日期范围汇总每日计划分摊与登记工时，支持指定人员或“我”、项目、类型和时区，缺少到期日等情况单列。
- 检查本地 API Key 是否已配置。
- 用户确认后创建工作项、修改标题/负责人/属性、执行状态流转、登记实际工时。
- 用户确认后发送或回复、修改、删除评论，修改或删除实际工时，设置预估和剩余工时。

当前版本为 0.6.0，共提供 30 个 MCP 工具：19 个查询工具和 11 个需要用户确认的写工具。项目详情表单字段不等于新建工作项的完整必填规则。

## 写入前由你确认

AI 调用写工具后，服务先核验身份、读取目标，并通过客户端确认表单展示本次操作的站点、用户身份、目标和完整请求参数。勾选同意并提交后才发送写入；默认不勾选。拒绝、取消、超时或确认表单失败都不会写入。

- 客户端需要支持 MCP `elicitation.form`。不支持时返回 `CONFIRMATION_UNAVAILABLE`，仍可查询或使用 `previewOnly: true` 查看预览。安装向导支持某客户端，不代表其所有版本都支持确认表单。
- 不接受 `confirmed: true` 等工具参数代替用户确认。参数有变化，必须重新核对并确认；已有工作项、可执行工作流、目标评论或工时记录在确认期间变化时，本次操作会停止。
- 每个逻辑操作提供唯一 `requestID`。同一服务进程内重复调用原 ID 会复用原结果，不重复执行；修改参数不能复用该 ID。预览不会消耗执行 ID。
- 写入结果未知时不会自动重试。请先查询 ONES 核实是否已生效，再决定后续操作。请求记录只保存在当前服务进程内，重新连接后不提供跨进程去重保证。

创建、修改和流转需要 `write:project:issue`；评论需要 `write:project:issue-comment`；实际、预估、剩余工时分别需要 `write:project:issue-timeSpent`、`write:project:issue-timeEstimated`、`write:project:issue-timeRemaining`，还需具备身份和目标的读取权限。具体必填字段及可执行动作以 ONES 配置为准。

评论正文按官方接口声明限制为 128 字符。修改实际工时需要完整提供小时数、开始时间、登记人和描述，空描述表示清空；预估和剩余工时允许设为零。删除时展示原记录，本工具不提供恢复。无法读取到目标评论时会停止，不能把评论列表中未出现的记录当作不存在。

## 组合检索的范围

`ones_search_issues` 逐页读取工作项列表，再组合筛选。条件之间为 AND，负责人和状态的 ID 数组内部为 OR。默认最多扫描 3 页，每页最多 100 条；可设置 `maxPages: 1–10` 和 `pageSize: 1–100`，单批约 25 秒预算。`scan.returnedCount` 是本批匹配数，不是总数；有 `scan.nextCursor` 时保持筛选参数继续查询。`exhausted` 仅表示已扫描到来源末页，从中间游标开始时仍不能代表扫描了全部工作项。跨批结果由客户端按 ID 合并，数据并发变化时可能重复或遗漏。

时间筛选边界使用 Unix 秒，包含给定边界时间点。列表原始时间单位通过 `sourceTimeUnit` 指定，当前部署验证为微秒，默认 `microseconds`；其他部署可显式选 `milliseconds` 或 `seconds`，不按数值大小猜测。结果保留原始时间。当前部署列表没有 `updateTime`，使用更新时间筛选会排除无法判断的记录，并计入 `scan.unknownFieldCount`；即使扫描到末页，也不能宣称这类筛选结果完整。此工具不执行 ONESQL；后者的参数化与偏移分页兼容性仍待解决。

## 每日计划与登记工时

`ones_get_daily_hours` 是只读统计工具，不修改 ONES，不需要写入确认。传入团队、`startDate`、`endDate`（含两端，格式 `YYYY-MM-DD`），可选项目、类型、`userIDs` 或 `mineOnly: true`。

- 剩余待安排工时使用工作项自身的 `max(timeEstimatedHour - timeSpentHour, 0)`，扣减累计登记工时不限查询日期和登记人；不使用父子聚合的 `total*` 字段，也不再次扣减 `timeRemainingHour`。
- 默认从所选时区今天起，到到期日（含当天），按周一至周五平均分摊，不扣法定节假日。可通过 `allocationStartDate` 显式设置未来起算日，通过 `calendar: "calendarDays"` 改为自然日。分摊分母不随展示区间变化，周末到期时仍只分配到此前的有效工作日。
- 登记工时按记录的 `startTime` 工作日期汇总，整条记录归入当天，周末登记也保留。人员筛选对计划使用负责人，对登记使用工时记录的 `owner.id`；会读取其他负责人工作项上的登记，避免漏算。
- `timeZone` 默认 `America/Los_Angeles`，不采用执行机器的时区；中国业务日期可显式传 `Asia/Shanghai`。日期区间最多 366 天。过去日期可查登记，但计划只是当前快照预测，过去日期不补造历史计划。
- 缺少到期日、逾期、无有效分摊日、缺失工时字段等列入 `unallocated`。`remainingHoursKnown` 包括已知但无法分摊的余额，不能把每日计划为零解释成没有待办。默认不自动排除已完成状态；可显式提供 `excludePlannedStatusIDs`，仅排除计划，仍统计登记。
- `days` 返回逐日 `plannedHours`、`registeredHours` 及数量；`allocations` 返回各工作项的分摊天数、日均值和本区间合计。小时数输出保留八位小数，展示行合计可能有末位舍入差。
- `coverage.complete=false` 表示来源、权限、分页、字段或预算导致统计不完整；每日数值只代表已读且能判定的部分。`allKnownRemainingHoursScheduled=false` 表示不能把所有剩余余额都视为已安排，详见未分摊清单。即使读取完整，也仅覆盖当前权限可见的简单工时模式，不保证并发快照一致。

例如，让 AI 调用：

```json
{
  "teamID": "TEAM_ID",
  "startDate": "2026-11-12",
  "endDate": "2026-11-30",
  "timeZone": "Asia/Shanghai",
  "mineOnly": true
}
```

默认最多读取 100 个工作项、10 页工作项及每项 10 页工时，每页最多 100 条，总读取预算约 25 秒。可用 `maxIssues`（最高 500）、`maxIssuePages` 和 `maxWorklogPagesPerIssue`（各最高 20）调整限制；遇到不完整结果，可缩小项目范围或提高页数上限后重新计算，不能直接相加不同人员或重复范围的报告来推算完整计划。

## 让 AI 帮你安装

将下面的提示词复制给支持本地操作的 AI 助手，并替换源码目录。也可以附上团队 ID，让 AI 完成一次真实查询验证。

```text
请用 npx @suplaser/onces-mcp@latest setup 为当前 AI 客户端配置 MCP；需要使用本地源码时，从 <项目完整路径> 构建运行 setup。
API Key 使用项目自带的安全输入引导，完成后连接服务并列出可用工具。
```

## 手动安装

### 1. 准备并构建项目

安装 [Node.js](https://nodejs.org/)（推荐 26），在项目目录执行：

```sh
git clone https://github.com/suplaser/ones-mcp.git
cd ones-mcp
npm install
npm run build
```

### 2. 一键配置 AI 客户端

在项目目录执行：

```sh
npm run setup
```

用空格选择客户端，按 Enter 查看并确认配置计划。支持 Codex、Claude Code、Cursor、Gemini CLI、VS Code、Windsurf 和 OpenCode。完成后重启或重新连接所选客户端。

已有配置会先备份，再合并 ONES MCP；其他服务和权限设置会保留。重复执行不会重复添加，遇到同名的其他服务会停止并提示。此步骤不需要 API Key，也不会把 Key 填入客户端配置。

也可以指定客户端或只看预览：

```sh
node dist/index.js setup --client codex,cursor --yes
node dist/index.js setup --client codex --dry-run
```

配置会绑定本次运行所在的安装目录，请保留该目录；移动或更新后重新运行 `setup`。

<details>
<summary>手动添加配置</summary>

也可在客户端 MCP 设置中添加以下配置，将路径替换为本机项目路径：

```json
{
  "mcpServers": {
    "ones": {
      "command": "node",
      "args": ["E:/workspaces-cqwy-oa/ones-mcp/dist/index.js"]
    }
  }
}
```

不同客户端的配置入口和格式可能略有不同。若通过表单添加，启动命令填 `node`，参数填项目中的 `dist/index.js` 完整路径。

</details>

### 3. 配置个人 API Key

Windows 首次启动时，若没有保存 API Key，会自动打开 [ONES 个人 API Key 设置页](https://ones.cn/project/#/profile/personal_openapi_keys) 和一个独立终端：

1. 登录 ONES，在设置页创建个人 API Key，并授予所需的查询权限；使用写工具时再授予对应写入权限。
2. 将 Key 值粘贴到弹出的终端，按 Enter 保存。请使用用户级个人 API Key。
3. 返回 AI 客户端，即可开始查询。

输入和粘贴时都显示等长的 `*`。Key 保存在系统凭据库中，不会写入项目文件或日志。已有 Key 时会直接使用，无需重复输入。

也可以在项目目录手动配置或更换 Key（macOS/Linux 请使用此方式）：

```sh
npm run auth:login
```

若已有 Key，会先询问是否覆盖，默认保留。保存新 Key 后，下次查询即可使用，无需重启服务。

### 4. 开始对话

连接成功后，可以向 AI 提出这样的请求：

- “验证我的 ONES 用户身份和权限范围。”
- “列出我能访问的团队，再查询选定团队的项目列表。”
- “查询团队 TEAM_ID 的项目列表。”
- “查看这个项目的详情。”
- “查询团队 TEAM_ID 的工作项列表，继续读取下一页。”
- “查我负责的、标题含‘登录’且不在指定已完成状态中的工作项，说明扫描范围并继续翻页。”
- “查看这个工作项的详细信息。”
- “搜索团队里的张三，获取他的用户 ID。”
- “查看团队的工作项类型，以及这个项目的详情表单字段。”
- “先查询属性目录，再查看优先级属性有哪些选项。”
- “查看这个工作项当前可以执行哪些状态流转。”
- “读取这个工作项的评论。”
- “查询这个工作项已登记的工时，继续翻页，并查看其中一条记录的详情。”
- “按中国时区列出本月每天我负责工作项的剩余计划分摊和我登记的工时，周一至周五分摊，单列无到期日和逾期工作项，并说明数据是否读全。”
- “为这个项目准备一条需求，先查询类型和必填属性，展示完整内容后让我确认创建。”
- “把这个工作项的负责人改为张三，由我确认后执行。”
- “先查可执行工作流，再让我确认是否关闭这个工作项。”
- “为这个工作项登记指定日期的 1.5 小时实际工时，核对登记人和开始时间后让我确认。”
- “为这个工作项回复一条评论，展示原评论和回复内容后让我确认。”
- “修改这条工时记录，列出完整的新记录后让我确认。”
- “把这个工作项的剩余工时设为 2 小时，由我确认后执行。”

通常先让 AI 查询团队列表，再选择要查询的团队，无需自己查找团队 ID。若使用带 `TEAM_ID` 的示例，请替换为实际团队 ID。AI 可以使用查询返回的 ID 继续查看详情。项目、工作项、用户和属性目录分批返回；需要完整列表时，请明确要求继续翻页。

已登记工时列表也支持游标翻页；团队状态、工作项类型和评论接口未提供可指定的翻页参数。评论返回直接数组时不补造分页信息。属性选项使用 `offset/limit`，但本机验证发现部分部署会忽略 `offset`，出现重复选项时应停止翻页，不能宣称已获取完整目录。

## 通过 npx 使用

可以通过 npm 上的最新版本直接运行配置向导：

```sh
npx @suplaser/onces-mcp@latest setup
```

也可以直接将 npm 上的服务添加到客户端。若使用本地修改，请按上面的源码方式构建并配置：

```json
{
  "mcpServers": {
    "ones": {
      "command": "npx",
      "args": ["--yes", "@suplaser/onces-mcp"]
    }
  }
}
```

## 常见问题

- **如何检查 Key 是否可用？** 在项目目录运行 `npm run auth:status` 可检查是否已保存；让 AI 验证 ONES 当前用户身份和权限范围，可检查远端是否接受凭据。具体资源是否可访问，以实际查询结果为准。
- **查询提示认证或权限不足？** 检查 Key 是否有效、是否授予查询权限，以及你的 ONES 账号能否访问相应团队和项目；需要更换时运行 `npm run auth:login`。
- **使用其他 ONES 部署地址？** 默认连接 `https://sz.ones.cn`。其他部署可在客户端的服务环境变量中设置 `ONES_BASE_URL` 为实际站点地址；若 API 地址不同，再设置 `ONES_API_BASE_URL`。
